# 从实验版 0.1.22 迁移

当前目标为 **0.2.0**，以 Owner 已批准的 0.1.5 实现为功能依据。从正式开发版 0.1.5 升级也使用相同存储、scriptId、交换格式、密钥偏好和预设 ID；没有新的配置转换。真实酒馆持久化检查为 **PENDING — post-release manual smoke test / follow-up**。

旧 0.1.22 没有 Package v1 首行身份，不等于正式包安装。Hub 不自动识别／停用旧 Director，当前工程没有修改 Hub Core 或旧版白名单。

首次安装前：

1. 导出导演规划、最高指令和主 API 提示词；记下接口地址、模型、输出上限和超时。
2. 停止生成，停用旧 0.1.22；确认它不会和新脚本同时启用。
3. 从 [0.2.0 Release](https://github.com/SheepSheepLab/MieMie-Story-Director/releases/tag/v0.2.0) 下载并导入 `MieMie-Story-Director-Extension-0.2.0.json`，或由兼容 Hub 检查仓库后安装。
4. 在同一酒馆／浏览器来源检查三套旧库、启用状态、排序和接口配置。
5. 检查密钥偏好、独立入口和 Hub 入口；每次只运行一个故事导演。

正式包继续读取历史 extension storage `meeme_story_planner_v1`。三库分别为 plannings、requirements、writers；接口字段与原行为保持不变。公开 artifact 的 data 为空不表示清空这个独立存储。不要删除扩展变量、重置配置或把个人导出数据打入公开包。

0.1.5 更新三条内置提示词，保留已有 DIY 与启用状态：未修改过的旧默认替换为新的默认；旧默认若已被修改，则改用普通 DIY ID，保留原文并继续允许编辑。缺失的默认在列表底部补回为关闭状态，包括先前清空过的最高指令／主 API 库。固定默认不可编辑、删除或排序，可以关闭或再次开启。已有导演规划不清空，只有首次安装默认留空。此读取过程不立即写存储；后续用户操作沿用原保存流程。

历史密钥偏好继续是 `meeme_story_director_api_key_v1`。只有记录的基础地址与配置相同，旧记住的密钥才恢复。未记住的 Key 原本只在当前页面，停用／刷新后需要重新填写；换浏览器、酒馆来源或清理 localStorage 也不会自动保留。

Phase 5 使用最终安装产物与原始 0.1.22 分别读取同一份模拟旧存储，验证三库、API 字段、关闭条目、修改后的保存位置、记住／不记住／清除／地址不匹配密钥行为。还验证原版 Hub 的安装结果实际启动生产入口并发出模拟主／副请求。

这不是已经替 Owner 安装或迁移真实酒馆的声明。真实持久保存与设备检查仍需按 `PREFLIGHT.md` 人工完成。重复运行 guard 属于既有保护，不能替代事先停用旧脚本。
