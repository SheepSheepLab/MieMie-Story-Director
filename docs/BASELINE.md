## 冻结流程

1. 当前请求经酒馆组装并产生 READY 标记后读取当前咩咩预设；识别故事模式和既有预设 ID。
2. 解析启用条目对规划变量的 set／add 来源，并读取本轮已展开变量值；来源只用于追踪，不重新执行写入。
3. 对副 API 的 system／developer 上下文移除原指定格式片段与变量；历史消息保留。
4. 在原格式位置插入「导演规划」（预设＋DIY）及「最高指令」；固定 system 为“你是本轮的故事导演。”。
5. 调用非流式副 API，使用当前模型、tokens、timeout。协议错误、截断或无正文阻止主请求。
6. 提取唯一非空 story_scene 内文；主 API 请求副本在玩家原位置换入大纲，在原故事模式位置换入自动包裹的主 API 提示词。
7. 主请求保留其余已组装上下文、语言／格式模块、角色、元数据及 transport 参数；不修改保存的玩家输入。

normal／swipe／regenerate 进入导演，continue 及当前其他类型保持原流程。取消、超时、切聊天、消息变更、重复请求及错误恢复的具体语义均以冻结脚本实际运行结果为准，包含 [Deferred](DEFERRED.md) 的现状。

## 存储与工具行为

三套库的多选、顺序、自动保存、已有迁移、导入导出、删除和默认条目行为冻结。变量模板保存原文，发送时展开；主 API wrapper 由脚本补齐。

API 地址、模型选择／手填、最大输出 token、超时、保存接口、模型列表和连接测试行为冻结。Key 默认页面内，主动勾选后保存在既有浏览器 key；提示词导出不包含配置或密钥。

Debug 的状态／用量、规划来源、副请求、完整报告、提取大纲和主消息内容冻结；完整上下文仍可能包含用户数据，测试只使用虚构样本。

## 回归原则

相同固定输入下，候选源码必须与冻结原版得到相同的 planning、director prompt、filter、scene、writer messages、请求路由与错误。差异默认是候选 Regression，不能以“更合理”为理由替换预期。

固定结果仅由冻结原版生成。`record-baseline.mjs` 是一次性记录工具，拒绝覆盖已存在的 golden；npm test 不执行它。锁文件同时验证参考脚本、核心、断言与 golden 未改变。
